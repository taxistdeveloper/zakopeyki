## 1. ЦЕЛЬ И СТРАТЕГИЯ РЕГРЕССИИ

Цель регрессионного тестирования — гарантировать, что исправление обнаруженных дефектов (взимание комиссии, защита от каскадного удаления заказов, настройка CSRF и окна споров) не нарушит сопредельные модули:
* Процесс создания и оплаты заказов;
* Логистические расчеты и регистрацию накладных СДЭК;
* Баланс кошелька и историю транзакций;
* Управление статусами аукционов и возврат холдированных ставок.

## 3. СЦЕНАРИИ АВТОМАТИЗИРОВАННОГО ПРОГОНА

Перед любым релизом или слиянием ветки обязателен запуск следующего набора команд:

1. **Синтаксическая проверка:**
   ```bash
   find app config -name "*.php" -exec php -l {} + | grep -v "No syntax errors detected"
   ```
2. **Прогон автономных тестов СДЭК и логистики:**
   ```bash
   for f in tools/run_*.php; do echo "Running $f"; php "$f"; done
   ```
3. **Прогон unit-тестов сервисов (после установки phpunit.phar):**
   ```bash
   php tools/phpunit.phar --configuration phpunit.xml
   ```
4. **Проверка логов транзакций на отсутствие расхождений:**
   ```sql
   SELECT user_id, SUM(amount) FROM wallet_transactions GROUP BY user_id;
   ```

## 4. СТАТУС ВНЕШНИХ ИНТЕГРАЦИЙ

* **Halyk ePay:** Тестовый режим функционирует для оплаты отдельных заказов. Для прямого пополнения баланса кошелька шлюз не интегрирован (дефект QA-0004).
* **СДЭК API v2:** Отличная степень интеграционной проработки. Калькулятор, валидатор точек, FSM трекинга и печатные формы на 100% подтверждены тестами.
* **Ollama AI (ZAK):** Архитектура построена грамотно. Реализована защита от Prompt Injection. При недоступности локального сервера LLM отрабатывает эвристический RAG-fallback.
* **AML АФМ РК:** Алгоритм валидации контрольной суммы ИИН Казахстана работает корректно, фильтрация по спискам подтверждена.
* **FreedomPay:** Контур депрекейтирован и отключен по умолчанию.

## 5. РЕКОМЕНДУЕМЫЙ ПЛАН ДЕЙСТВИЙ И КРИТЕРИИ ДОПУСКА

Для допуска платформы Zakopeyki.kz к этапу промышленной эксплуатации необходимо:

1. **Немедленно устранить дефект P0 (QA-0003):** Изменить внешний ключ на `ON DELETE RESTRICT` и запретить удаление объявлений с активными заказами или ставками на аукционе.
2. **Исправить финансовую логику (QA-0001, QA-0002):** Добавить автоматическое удержание 10% комиссии продавца в `EscrowService::settle()` и скорректировать срок подачи претензий на 24 часа.
3. **Реализовать боевой эквайринг пополнения кошелька (QA-0004):** Запретить симуляцию денег в боевом режиме.
4. **Устранить дефекты P2 (QA-0005, QA-0006, QA-0007):** Подключить серверный розыгрыш, закрыть дыру в накрутке лайков и добавить роуты микрозадач в список исключений CSRF.
5. **Провести повторный регрессионный прогон (Фаза E).**

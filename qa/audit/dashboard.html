04. Единый реестр дефектов платформы

Все 9 выявленных несоответствий с доказательствами из исходного кода

P1 ВЫСОКИЙ QA-0001 Эскроу / Финансы ПОДТВЕРЖДЁН

Отсутствует взимание 10% комиссии платформы с продавца при завершении сделки

В EscrowService::settle() продавец получает 100% стоимости товара ($amountToSeller = $total - $amountToBuyer). Утвержденная бизнес-модель площадки предусматривает удержание 10% с продавца. В коде удерживается только 3% сбор покупателя.

Доказательство: app/Services/EscrowService.php:508-512
- $wallet->releaseFromEscrow($sellerId, $amountToSeller, $orderId); // отдаёт 100% продавцу
+ $payout = $amountToSeller - round($amountToSeller * 0.10); // необходимо удержать 10%
P1 ВЫСОКИЙ QA-0002 Споры / Эскроу ПОДТВЕРЖДЁН

Несоответствие окна открытия спора: в коде задано 3 дня (72ч) вместо утвержденных 24 часов

Константа EscrowService::INSPECT_DAYS = 3 выставляет срок проверки inspect_until на 3 суток. Продавцы ждут разблокировки средств 72 часа вместо 24 часов.

Доказательство: app/Services/EscrowService.php:18
public const INSPECT_DAYS = 3; → требуется привести к регламенту 24 часа.
P0 КРИТИЧЕСКИЙ QA-0003 Целостность данных / Заказы ПОДТВЕРЖДЁН

Каскадное удаление активных заказов (ON DELETE CASCADE) при удалении лота продавцом

В ProfileController::deleteLot() проверяется только факт владения объявлением. Проверка наличия активных оплаченных заказов отсутствует. Внешний ключ таблицы orders имеет свойство ON DELETE CASCADE, из-за чего MySQL автоматически стирает строку оплаченного заказа, теряя финансовый след эскроу.

Доказательство: database/schema.sql:155
FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
P1 ВЫСОКИЙ QA-0004 Кошелек / Платежи ПОДТВЕРЖДЁН

Отсутствие реального эквайрингового шлюза для пополнения и вывода средств с кошелька

Пополнение кошелька работает только при активном флаге allow_simulated_payments = true, начисляя виртуальные тенге напрямую из POST-запроса. При отключении симуляции операция блокируется ошибкой wallet.payments_disabled. Реальный эквайринг для кошелька не реализован.

Доказательство: app/Controllers/WalletController.php:41-45
if (!($GLOBALS['appConfig']['allow_simulated_payments'] ?? false)) { $_SESSION['error'] = t('wallet.payments_disabled'); ... }
P2 СРЕДНИЙ QA-0005 Live Commerce ПОДТВЕРЖДЁН

Механика розыгрыша 500 сердец в эфирах — визуальный мок без серверной логики

Сервер только хранит метаданные розыгрыша goal: 500. Серверная таблица участников, фиксация достижения цели и выбор победителя при завершении стрима отсутствуют.

P2 СРЕДНИЙ QA-0006 Безопасность / Стримы ПОДТВЕРЖДЁН

Неограниченная накрутка лайков стримов без авторизации и rate-limit

Эндпоинт POST /streams/live/like открыт для неавторизованных посетителей и не имеет защиты от спама, что позволяет накручивать счетчик до 5000+ за секунды.

P2 СРЕДНИЙ QA-0007 API / Микрозадачи ПОДТВЕРЖДЁН

Эндпоинты API микрозадач блокируются проверкой CSRF

Роуты /api/v1/micro-tasks/* не добавлены в список csrfExempt() в Router.php, вызывая отказ 419 для внешних клиентов.

P4 ТЕХДОЛГ QA-0008 Архитектура ПОДТВЕРЖДЁН

Неиспользуемый «сиротский» класс app/ApiRouter.php

Класс фигурирует только в одном unit-тесте, но никогда не вызывается в веб-приложении.

P3 НИЗКИЙ QA-0009 База данных ПОДТВЕРЖДЁН

Расхождение имени базы данных (zakapeiku против zakopeyki)

В database/schema.sql создается база zakapeiku, а в config/database.php указано имя zakopeyki.

05. Технические задания на исправление для Cursor

Готовые промпты и инструкции с точной локализацией файлов и критериями приемки

P0

Задача 1: Устранить каскадное удаление заказов (QA-0003)

Исправь дефект QA-0003: в ProfileController::deleteLot() продавец может удалить объявление с активными заказами, что из-за ON DELETE CASCADE в database/schema.sql приводит к удалению оплаченных заказов из orders.

1. В app/Models/Order.php добавь метод hasActiveOrdersForProduct(int $productId): bool, проверяющий наличие заказов в статусах кроме 'completed', 'cancelled', 'refunded'.
2. В app/Controllers/ProfileController.php в deleteLot() добавь проверку: если hasActiveOrdersForProduct возвращает true, прерывать операцию, выставлять flash-ошибку 'Невозможно удалить товар с активным заказом' и редиректить в профиль.
3. Добавь проверку на активный аукцион с ненулевым числом ставок.
4. Создай файл database/migrate_fix_order_cascade.sql для изменения внешнего ключа fk_orders_product на ON DELETE RESTRICT.
P1

Задача 2: Удержание 10% комиссии платформы с продавца (QA-0001)

Исправь дефект QA-0001: в EscrowService::settle() продавец получает 100% стоимости товара, 10% комиссия площадки не удерживается.

1. В app/Services/EscrowService.php добавь константу SELLER_COMMISSION_PERCENT = 10.
2. В методе settle() при расчете выплаты продавцу:
   $sellerCommission = $amountToSeller > 0 ? (int) round($amountToSeller * self::SELLER_COMMISSION_PERCENT / 100) : 0;
   $payoutToSeller = $amountToSeller - $sellerCommission;
3. Начисляй продавцу $payoutToSeller через $wallet->releaseFromEscrow().
4. Добавь в Wallet::collectPlatformCommission($sellerCommission, $orderId, 'seller_commission_10pct') и зафиксируй в FinanceJournalService.
5. Не списывай комиссию при полном возврате покупателю ($amountToSeller === 0).
P1

Задача 3: Окно открытия споров ровно 24 часа (QA-0002)

Исправь дефект QA-0002: в EscrowService.php задано INSPECT_DAYS = 3 (72 часа), что противоречит заявленной бизнес-модели площадки (24 часа на подтверждение товара после вручения).

1. В app/Services/EscrowService.php замени INSPECT_DAYS на INSPECT_HOURS = 24.
2. При переводе заказа в статус 'delivered' устанавливай inspect_until как time() + INSPECT_HOURS * 3600.
3. В ReturnService::processTimedActions() и EscrowService::processDeadlines() проверь корректную авто-завершаемость сделок через 24 часа.
P2

Задача 4: CSRF-исключение для API микрозадач (QA-0007)

Исправь дефект QA-0007: в app/Core/Router.php метод csrfExempt() не исключает роуты /api/v1/micro-tasks/*, из-за чего клиенты API получают 419 ошибку.

В app/Core/Router.php добавь в метод csrfExempt:
if (str_starts_with($path, '/api/v1/micro-tasks/')) {
    return true;
}

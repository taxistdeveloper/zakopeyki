# Аудит: функции сайта vs мобильное приложение

Дата: 14.11.2026. Сайт — ветка `feature/contests-module` (на ней работает zakopeyki.kz),
приложение — `mobile/` (Flutter). Сверка по маршрутам `config/routes.php` (без админки) и экранам приложения.

Обозначения: ✅ есть в приложении · 🟡 частично · ❌ нет.
«API» — есть ли метод в `/api/mobile/v1`: **есть** / **нет** (надо писать на сервере).

## Итог

Ядро маркетплейса (каталог → карточка → корзина → оплата → сделка → чат) работает нативно.
Не хватает в основном: **возвратов и отзывов по сделке**, **продвижения объявлений**, **удаления аккаунта**,
и «социальных» разделов сайта (истории, эфиры, конкурсы, бонусы, курсы, биржа заданий).

## Технические замечания

1. **Отличия от сайта, которые не видно в таблице**
   - Новые сообщения приходят опросом раз в 4 с при открытом чате; push-уведомлений нет (нужен FCM + отправка с сервера при `Notification::createFor`).
   - Отметка «прочитано» у своих сообщений обновляется только при повторном открытии диалога.
2. **Время.** API отдаёт даты с часовым поясом PHP. На локальном MAMP Алматы = `+06:00` (устаревшая база часовых поясов; с 2024 года Казахстан — `+05:00`). Проверить `date.timezone` и tzdata на боевом сервере.
3. **Выключенные на сервере способы оплаты.** Пополнение и вывод кошелька в приложении скрываются, если на сервере нет Halyk / не разрешена симуляция — так же, как на сайте.
4. **Документы** (оферта, политика, правила) — страницы сайта внутри приложения. Это нормально.

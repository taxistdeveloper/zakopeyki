# Закопейки — Android-приложение (Flutter)

Нативное Android-приложение маркетплейса: данные с сайта через мобильный API, свой мобильный дизайн.

Все разделы — нативные экраны на `/api/mobile/v1`:

- каталог, поиск, фильтры, карточка товара, избранное, «Поделиться»;
- вход (email + 2FA, Google), регистрация, сброс пароля;
- корзина, оформление (сделка, доставка, оплата картой/кошельком);
- мои покупки и продажи, действия по сделке;
- мои объявления: подача, правка, удаление, фото;
- **сообщения** (список диалогов, переписка, непрочитанные);
- кошелёк (баланс, история, пополнение картой);
- уведомления (ссылки открывают нужный экран приложения);
- личные данные, пароль, двухфакторная аутентификация;
- поддержка (обращения и переписка);
- профиль продавца (объявления, отзывы, подписка);
- торги на аукционе (ставка, «купить сейчас», история ставок);
- ИИ-помощник ZAK с голосовым вводом и **голосовым пробуждением «Зак»** (см. ниже).

Страницами сайта внутри приложения остаются только юридические документы (оферта, политика, правила) и правка объявлений типов, которых нет в API приложения (аукцион, услуги, СДЭК).

Оплата картой — форма банка Halyk ePay (WebView), возврат в приложение по `zakopeyki://payment-result`.

## Как работает сессия

Сервер — боевой мобильный API `/api/mobile/v1` (`app/Controllers/Api/Mobile/`, ветка `feature/contests-module`). Ответы `{success, data, meta?}` / `{success:false, error:{code, message, fields?}}`.

1. При первом запуске генерируется `device_id` (Keystore), он уходит в заголовке `X-Device-Id`.
2. Вход: `POST /auth/login` → `access_token` (15 мин, только в памяти) + `refresh_token` (60 дней, Keystore). При 2FA — `challenge_token` → `POST /auth/2fa`.
3. Запросы с `Authorization: Bearer`; на 401 клиент один раз делает `POST /auth/refresh` и повторяет запрос.
4. Пока сайт в режиме «скоро открытие», каталог (`site_closed`) доступен только admin и аккаунтам с `site_access`.
5. Встроенный WebView (документы, платёжная форма банка) не делит сессию с приложением — API работает только по Bearer.

Ссылки `/product/{id}` внутри WebView открывают нативную карточку, `tel:`/`wa.me`/`t.me` — внешние приложения. `<input type="file">` на сайте открывает камеру/галерею.

## Вход через Google

Нативный Google Sign-In (`google_sign_in`) → ID-токен → `POST /api/mobile/v1/auth/google`. Токен выпускается для web-клиента сайта (`kGoogleServerClientId` в `lib/config.dart`).

Чтобы заработало, нужно один раз настроить:

1. **Google Cloud Console** (проект, где web-клиент сайта) → Credentials → Create OAuth client ID → **Android**:
   package `kz.zakopeyki.app`, SHA-1 ключа подписи. Для текущих сборок (debug-ключ этой машины):
   `2D:8A:79:F3:2D:97:7E:D9:BA:EA:39:62:F9:28:CB:80:E5:1F:90:A0` (debug.keystore пересоздан 22.11.2026; старый `50:70:18:AE:…:DD:53` больше не действует). При переходе на свой release-ключ / Google Play App Signing — добавить и их SHA-1.
2. **Сервер**: переменная окружения `GOOGLE_MOBILE_CLIENT_IDS=<web client id сайта>` (см. `config/mobile.php`). Пока она пустая, API отвечает `provider_disabled`.

## Голосовое пробуждение «Зак»

Скажите «Зак» («Zak») — откроется помощник ZAK, ответит голосом «Да, слушаю вас» и начнёт слушать вопрос; после паузы распознанный текст уходит в чат, а ответ ZAK зачитывается вслух. Если ZAK уже открыт, «Зак» просто запускает диктовку. Вопрос можно надиктовать и кнопкой микрофона в поле ввода ZAK.

- **Включение**: меню → «Голосовое пробуждение» или Профиль → «Голосовое пробуждение». По умолчанию выключено, выбор хранится на устройстве (`wake_word_enabled` в secure storage).
- **Разрешение**: `RECORD_AUDIO` запрашивается при включении (`permission_handler`). Без него функция не включается.
- **Когда слушает**: только пока приложение на экране. При уходе в фон микрофон освобождается (Dart — `AppLifecycleListener`, натив — `MainActivity.onStop`). На время диктовки в ZAK и прямого эфира слушатель ставится на паузу (`WakeWord.hold/release`), чтобы не делить микрофон.
- **Индикатор**: пока микрофон слушает, слева внизу пульсирует синий значок микрофона (нажатие открывает настройку), а подпись кнопки ZAK на главной меняется на «Скажите «Зак»». Android 12+ дополнительно показывает свой зелёный индикатор микрофона.
- **Как устроено**:
  - слово-пробуждение — офлайн-распознавание [Vosk](https://alphacephei.com/vosk/) (`com.alphacephei:vosk-android`, натив: `android/app/src/main/kotlin/.../WakeWordPlugin.kt`, каналы `kz.zakopeyki/wake_word`). Речь распознаётся полным словарём модели прямо на телефоне, приложение лишь ищет в ней «зак» (модель пишет его также как «заг»/«зэк»); текст и звук никуда не отправляются и не сохраняются. Грамматика из одного слова (`["зак", "[unk]"]`) не подходит: Vosk притягивает к «зак» почти любую фразу. На синтезированных фразах полный словарь дал 9/9 срабатываний на «Зак» и 0 ложных на 26 похожих («закажи», «закат», «казак», «зачем»…);
  - модель `vosk-model-small-ru-0.22` (~45 МБ) **скачивается один раз при включении** с alphacephei.com в `filesDir/vosk` — APK она не увеличивает (нативные библиотеки Vosk добавляют к APK несколько МБ на ABI);
  - вопрос после «Зак» распознаёт системный сервис речи Android (`speech_to_text`, `ru_RU`) — обычно Google, может работать через сеть;
  - в release-сборке R8 не должен переименовывать JNA и Vosk — правила в `android/app/proguard-rules.pro` (без них включение падает с `UnsatisfiedLinkError`);
  - Dart: `lib/wake_word.dart` (состояние, разрешение, очередь start/stop), `lib/widgets/wake_word_ui.dart` (обработчик «Зак», индикатор, настройка), диктовка — в `lib/screens/assistant_screen.dart`.
- **Ограничения**: модель русская — английское «Zak» с сильным акцентом узнаётся плохо, лучше говорить по-русски «Зак». Проверено пока только на синтезированной речи; на живых голосах и в шуме возможны пропуски и ложные срабатывания. Точность ниже, чем у специализированных движков (Picovoice Porcupine). Если понадобится лучше — заменить `WakeWordPlugin` на Porcupine с собственной моделью «Zak» (нужен AccessKey Picovoice), Dart-часть не меняется. Работа в фоне (foreground service) не реализована сознательно.

## Голос ZAK

ZAK говорит тем же голосом, что на сайте: серверный синтез из `config/ai.php` → `tts` (сейчас `edge_neural`, голос **ru-RU-SvetlanaNeural**; при `AZURE_SPEECH_KEY` — Azure). Голос выбирает сервер, в приложении он не зашит.

- **Эндпоинт**: `POST /api/mobile/v1/assistant/tts {text, language}` (`mobile/server_update/.../AssistantApiController::tts`) отдаёт сам MP3 (`audio/mpeg`). Ссылки сайта `/ai/tts/audio/{token}` не подходят: они привязаны к PHP-сессии, а у приложения её нет. Если серверный голос недоступен (провайдер `browser`, нет edge-tts, сбой) — `503 tts_unavailable`, и приложение молчит. Лимит запросов — отдельный ключ `tts:` в `RateLimiter`, сообщения в чат он не расходует.
- **Когда звучит**: «Да, слушаю вас» после «Зак» (заранее скачивается и хранится в памяти); ответ на вопрос, заданный голосом; все ответы — если включить динамик в шапке ZAK (по умолчанию выключено, хранится на устройстве `zak_auto_speak`). Новый вопрос, диктовка или уход с экрана обрывают речь.
- **Микрофон**: пока ZAK говорит, слушатель «Зак» на паузе (`WakeWord.hold('zak_voice')`), чтобы приложение не будило само себя.
- Код: `lib/zak_voice.dart` (загрузка и воспроизведение через `audioplayers`), `Api.assistantTts` в `lib/api.dart`.
- **Деплой**: эндпоинт заработает после выкладки `mobile/server_update` на сервер; до этого приложение просто не говорит, остальное работает.

## Запуск

```bash
flutter pub get
```

Против боевого сайта (по умолчанию `https://zakopeyki.kz`):

```bash
flutter run
```

Против локального MAMP из эмулятора Android:

```bash
flutter run --dart-define=SITE_URL=http://10.0.2.2/zakopeyki   # нужен локальный backend с веткой feature/contests-module
```

Сборка релиза (нужен ключ подписи, см. ниже):

```bash
flutter build appbundle --release
```

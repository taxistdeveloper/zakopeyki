# 04 — Хранение, безопасность, персональные данные, админка

## 1. Хранение файлов

```
storage/tryon/YYYY/MM/<32 hex random>.jpg     # без user_id и имени файла в пути
```

- `storage/` закрыт корневым `.htaccess` (`RewriteRule ^storage(/|$) - [F]`); дополнительно `storage/tryon/.htaccess` с `Require all denied` (как `public/uploads/disputes/.htaccess`) на случай иной конфигурации веб-сервера. На nginx — эквивалентный `deny` [проверить конфиг прода, D4].
- Права каталога `0700`/файлов `0600` для пользователя PHP.
- Выдача только через `TryOnController::result/photo`: проверка `owner_user_id == Auth::id()`, `deleted_at IS NULL`, затем `readfile()` с `Content-Type: image/jpeg`, `Cache-Control: private, no-store`, `Content-Disposition: inline`.
- Срок хранения: `tryon_retention_hours` (24 ч по умолчанию); очистка — воркер `--cleanup` каждые 10 минут; при удалении — `unlink` + `storage_path = NULL`, `deleted_at = NOW()`.
- У провайдера: Genlook — `output.keepForDays = 1` (минимум), `externalUserId` для полного удаления (`DELETE /tryon/v1/customers/{externalUserId}`); FASHN — base64-входы удаляются после обработки, ссылки результатов живут 3 дня, удаление записей — по email [ограничение, отражено в согласии].

## 2. Обработка изображения (`TryOnImageValidator`)

1. `$_FILES` ошибки, размер ≤ 10 MB (лимит Genlook).
2. `UploadHelper::isAllowedUpload($tmp, $name, ['jpg','jpeg','png','webp'])` — существующая проверка расширения + MIME + `getimagesize`.
3. До декодирования: `getimagesize` → ширина/высота в пределах 512…6000 px, площадь ≤ 36 MP (защита от «pixel bomb»).
4. Декодирование GD, поворот по EXIF Orientation, ресайз до 2048 px по длинной стороне.
5. **Перекодирование в JPEG q90** — удаляет EXIF (включая GPS), ICC-мусор и полиглот-нагрузку.
6. `sha256` уже перекодированного файла.

HEIC: iOS Safari при `accept="image/*"` обычно отдаёт JPEG [проверить на устройстве в PHASE 3]; HEIC на сервере не принимаем.

## 3. SSRF и внешние запросы

- Фото покупателя и товара отправляются провайдеру **файлом** (multipart/base64), не URL — сервер не раздаёт публичные ссылки на фото покупателя, а провайдер не ходит на наш хост.
- Загрузка фото пользователем по URL — **не поддерживается**.
- Скачивание результата (`resultImageUrl`): только `https`, хост из allowlist провайдера (`config/tryon.php`, заполняется фактическими CDN-хостами в PHASE 2), `CURLOPT_FOLLOWLOCATION = false`, резолв DNS и запрет приватных/loopback/link-local адресов, таймаут 20 с, лимит 15 MB, проверка, что ответ — изображение (`getimagesizefromstring`), затем перекодирование в JPEG.
- Исходящие запросы — только на базовые URL из конфигурации.

## 4. Ключи и логи

- Ключи — только переменные окружения; в логах маскируются (`gk_****`).
- В логи не пишутся: фото, base64, URL результатов, `externalUserId`, тексты ошибок провайдера целиком. Пишутся: `job public_id`, провайдер, HTTP-код, `error_code`, длительность.
- Ошибки пользователю — только из таблицы кодов (02-api-contracts.md).

## 5. Доступ и злоупотребления

| Угроза | Мера |
|---|---|
| Просмотр чужих фото | `public_id` случайный + проверка владельца; чужое → 404 |
| CSRF | `X-CSRF-Token` на POST/DELETE |
| Перебор/спам | `RateLimiter` (6/мин, 30/ч), лимит активных заданий, дневной/месячный лимит |
| Перерасход | месячный бюджет с резервом стоимости под `GET_LOCK('tryon_budget')`; при исчерпании — 503 `budget_exhausted` и уведомление админу |
| Фото третьих лиц / неприемлемый контент | согласие с подтверждением «на фото я или лицо, давшее согласие»; модерация провайдера (`ContentModerationError`/аналог) → `failed/content_moderation` |
| Админы видят фото | **по умолчанию нет**: в админке только метаданные; доступа к файлам из админки нет |
| Утечка через кеш/CDN | `no-store`, без публичных URL |

## 6. Персональные данные (РК) — требует юриста (D5)

План, который нужно подтвердить юристом до запуска в прод:
- Отдельное явное согласие перед каждой первой примеркой (версия согласия хранится в задании), текст ru/kk: цель (только генерация примерки), состав (фото), оператор, **трансграничная передача** конкретному обработчику (Genlook — ЕС; резерв FASHN — Великобритания/США), сроки хранения (24 ч у нас, ≤1–3 дня у обработчика), право удалить в любой момент.
- Закон РК № 94-V: требования к локализации баз ПД и трансграничной передаче (ст. 12, 16) [не подтв. трактовку]; возможная квалификация фото лица как биометрических данных.
- Обучение моделей на фото покупателей — запрещено: Genlook и FASHN заявляют отказ от обучения на данных клиентов; не включать opt-in.
- Обновить `/privacy` и `/data-policy` (существующие страницы, разрешены в stub-режиме).
- DPA с поставщиком (Genlook предлагает GDPR DPA).

## 7. Админ-панель (PHASE 4)

Страница `/admin/try-on` (роль `admin`; менеджер — при праве `tryon`, через `Auth::requirePermission`), пункт в `AdminNav`:

| Блок | Содержание |
|---|---|
| Управление | `tryon_enabled`, бета-пользователи, включённые типы, порядок/вкл. провайдеров |
| Лимиты | дневной/месячный на пользователя, активные, системная конкуренция |
| Бюджет | месячный потолок, израсходовано (сумма `cost_actual_micros`, иначе оценка), прогноз |
| Статистика | задания по статусам/провайдерам/дням, успешность, среднее время, топ `error_code` |
| Здоровье | последний успех/ошибка по провайдеру, доля ошибок за 1 ч, остаток кредитов (Genlook check-credits endpoint), состояние воркера (время последнего цикла) |

Фото покупателей в админке не отображаются.

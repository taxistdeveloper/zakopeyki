| Повторная отправка | `Idempotency-Key` хранится до успешного ответа — обрыв сети и повторный клик не создают второе задание |
| REST DELETE | `Router::delete()` (CSRF проверяется как для POST), `DELETE /api/v1/try-on/jobs/{id}`; POST-алиас сохранён |
| Удаление аккаунта | `User::deleteAccount()` вызывает `TryOnService::purgeUser()` (файлы у нас + данные у провайдера); работает и для удаления из админки |
| Тексты ru/kk | `tryon.listing_*`, `tryon.type.*`, `tryon.ui.*` (ключи ru и kk совпадают — проверено скриптом) |

## 4. Развёртывание (когда будет решение о запуске)

1. Переменные окружения на сервере: `TRYON_GENLOOK_API_KEY`, `TRYON_USER_HASH_SECRET` (случайные ≥32 символа). `TRYON_ALLOW_FAKE` на проде **не задавать**.
2. Схема создаётся автоматически при первом обращении (`ensureSchema`/`ensureColumn`) или вручную `database/migrate_tryon.sql` — по согласованию.
3. Cron: `* * * * * php /path/bin/tryon_worker.php --max-runtime=55 >> logs/tryon_worker.log 2>&1`.
4. Настройки: `tryon_beta_users` → проверка; затем `tryon_enabled=1`. Модуль по умолчанию выключен.
5. Обновить `/privacy` и `/data-policy` (согласие, трансграничная передача) — после юриста (D5).

# EXECUTIVE SUMMARY — MASTERING-00: аудит Zakopeyki.kz для мобильного приложения

> Дата: 2026-11-09 · ветка `feature/contests-module` (с незакоммиченными изменениями Try-On — учтены как есть) · режим: только чтение. Исходный код, конфигурация, зависимости, БД и окружение **не изменялись**; создана только папка `docs/mobile-audit/`.

## 1. Состояние проекта

- **Платформа функционально богатая и зрелая по бизнес-логике**: собственный PHP 8.1+ MVC без Composer (~126 тыс. строк PHP/JS), MySQL 8, 396 маршрутов, 59 моделей, 210 сервисов. Реализованы: каталог из 7 типов (новое/б/у/услуги/gigs/курсы/даром/обмен), escrow Safe Deal с 3% сбором покупателя и 10% комиссией продавца, окно осмотра 24 ч, возвраты/споры/арбитраж, доставка CDEK через абстракцию провайдера, чат, Stories, live-стримы, аукционы трёх типов, конкурсы, бонусы и рефералы, 8 платных услуг, Business-пакет и Seller API, ИИ-ассистент «Зак» (Ollama, RAG, голос whisper.cpp, TTS, подтверждение действий), Virtual Try-On.
- **Платформа не готова к мобильному клиенту на уровне API:** почти всё — серверный HTML с cookie-сессией и CSRF; токен-авторизации для пользователей нет; нет пагинации ленты; поиск через `LIKE`; медиа без превью и с относительными URL; корзина в сессии; нет push, нет realtime (только polling), live — P2P без TURN; нет английского языка; нет CI, мониторинга и бэкапов в репозитории.
- **Обнаружены критические проблемы безопасности**, которые нужно исправить **до** мобильной разработки, независимо от неё (см. §3).

Детали: [FEATURE_AUDIT_MATRIX.md](FEATURE_AUDIT_MATRIX.md), [REPOSITORY_MAP.md](REPOSITORY_MAP.md), [API_INVENTORY.md](API_INVENTORY.md).

## 2. Рекомендуемый стек

**React Native (New Architecture) + Expo (TypeScript)** с EAS Build/Submit/Update; **резерв — Flutter**. Причины: команда уже пишет на JS; TS-клиент генерируется из OpenAPI нового мобильного API; OTA-обновления под частые изменения продукта; все требования (камера/видео, SFU-live, push, платёжный Custom Tab, аудио для Зака) закрываются зрелыми модулями; EAS упрощает iOS-сборки. Выбор подтверждается 3–5-дневным spike (видеолента на бюджетном Android). Нативная разработка — дороже ≈ в 2 раза для данной команды. → [MOBILE_STACK_COMPARISON.md](MOBILE_STACK_COMPARISON.md)

Архитектура: новый слой `/api/mobile/v1` (тонкие JSON-контроллеры, bearer access + ротируемый refresh, envelope, курсорная пагинация, OpenAPI) поверх **существующих сервисов**; вынос логики объявлений/checkout/корзины из HTML-контроллеров в сервисы; push через FCM/APNs из единой точки `Notification::createFor`; оплата Halyk только через серверный callback. → [MOBILE_TARGET_ARCHITECTURE.md](MOBILE_TARGET_ARCHITECTURE.md)

## 3. Критические пробелы backend/API

1. **Critical:** `POST /payments/halyk/postlink` не аутентифицирован — можно зачислить деньги в любой кошелёк и перевести платежи в «оплачено» (`PaymentController.php:99-123,226-241`).
2. `allow_simulated_payments = true` в отслеживаемом `config/app.php:13`; реальное пополнение кошелька сломано (`WalletController.php:81` вызывает несуществующий метод).
3. Гонка двойного расчёта escrow (`EscrowService::settle` без блокировки; вызывается из GET `/orders/{id}`).
4. Ссылка сброса пароля выводится при `Host: localhost` (`AuthController.php:499-504`); KYC-документы бизнеса публичны и в git.
5. Нет мобильной авторизации, Sign in with Apple, корректного удаления аккаунта для Google-пользователей.
6. Нет пагинации/фильтров/сортировок/индексного поиска; нет медиа-превью; нет push и realtime; нет EN-локали.

→ [SECURITY_AUDIT.md](SECURITY_AUDIT.md), [BACKEND_GAP_ANALYSIS.md](BACKEND_GAP_ANALYSIS.md)
